## Core Products & Technology

### BDB — Brenych Dev Bridge

BDB is one of the studio's principal technical systems: an independent control / governance layer between AI models and real-world actions.

It is not a replacement for Claude, OpenAI, Codex, or MCP. It is a control layer around agent execution.

Relevant design:

- controlled agent execution
- explicit authority boundaries
- READ / STAGED_WRITE / PRIVILEGED_ACTION patterns
- human approvals
- provenance
- validation
- workspace isolation
- freshness / replay handling
- auditable result evidence
- model-agnostic architecture
- product integrations

Current research and integration directions include BDB × OpenAI / Codex / Astra, BDB × Claude, MCP, and multi-agent workflows. These are active engineering directions; unfinished integrations are not claimed as production-complete.

### BAF — Brenych Asset Forge

BAF is a current production-technology system for Blender-integrated 3D work.

It is used for structured asset generation and preparation, production pipelines, validation, controlled AI-assisted 3D workflows, and reusable environment / asset production. BAF is production tooling for broader game and environment work, not a portfolio experiment.

### SprintCRM

SprintCRM is internal CRM / workflow software rather than a marketing website.

Relevant characteristics:

- React / TypeScript
- Supabase
- PostgreSQL
- Auth
- RLS
- structured CRM and outreach-workflow logic
- product-bridge / controlled-agent integration work

The live system is not publicly available; it holds private operational data.

### Brenych Agent Interface

A current agent-native interface / product experiment.

The work explores agent-native interaction, WebMCP / MCP-adjacent workflows, requirement understanding, matching, evidence, focused output, and structured brief / handoff. The intent is that AI systems can use product capabilities rather than only browse static pages. This is not a portfolio redesign.

## Working Principles

- Build systems, not isolated screens.
- Treat AI agents as software actors with explicit boundaries.
- Keep consequential actions reviewable and auditable.
- Use explicit state, provenance, validation and evidence.
- Prefer reproducible systems over impressive demos that cannot survive real operating conditions.
- Treat interaction and visual quality as part of engineering quality.
- Use AI aggressively in development while keeping architecture, acceptance boundaries and final responsibility human-owned.

## About This Repository

This repository powers the current **Brenych Studio public website / portfolio system**.

It is a public positioning surface and case archive. It is not a complete inventory of current studio engineering.

The public site operates as:

## Product Structure

The site is organized around a route-driven and data-driven architecture:

- `src/data/cases.ts` stores the core Work registry, including metadata, content structure, related services, links, tags, production facts, and Open Graph assets.
- `src/data/workEvidence.ts` and `src/pages/EvidenceAtlas.tsx` drive the Work archive, featured-system selection, filters, and evidence framing.
- `src/data/immersive.ts` powers immersive case metadata, media inventories, proof labels, links, and search-readable content.
- `src/data/servicePages.ts` defines the service-entry pages as structured commercial routes with shared proof references and delivery logic.
- `src/data/caseStories.ts` and `src/data/availableSystems.ts` extend the archive with deeper storytelling and adaptation-ready system framing.

This keeps content, proof structure, and visual systems separate enough to evolve without turning the site into a hard-coded portfolio.

## Local Development

Install dependencies:

```bash
npm install
```

Run the dev server:

```bash
npm run dev
```

Run lint:

```bash
npm run lint
```

Build production assets:

```bash
npm run build
```

Preview the production build:

```bash
npm run preview
```

Node runtime for consistent local and Cloudflare builds is pinned in `.node-version`. The project currently targets:

```txt
^20.19.0 || >=22.12.0
```

## Deployment Notes

The site is deployed on **Cloudflare Pages**.

For production-safe publishing, the important checks are:

- successful `npm ci` and `npm run build`
- healthy public route responses
- correct canonical domain
- valid `sitemap.xml` and `robots.txt`
- working media assets on desktop and mobile
- stable no-overflow layout on public routes
